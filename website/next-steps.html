Section 9

Next steps, in priority order

  1. Make the single server recover itself

    Add the EC2 recover action to pugad-instance-unhealthy, take daily EBS snapshots with Data Lifecycle Manager, and run backups every 6 hours instead of nightly. Closes the Reliability gap; cuts worst-case data loss from 24 h to 6 h. Cost: cents.

  2. Stop the model running out of quota

    Move the Gemini key to a paid tier with a spend cap, or add a second model as a fallback, so customers never see "status 429". E-13 Add a clear friendly message when the model is unavailable.

  3. Put CloudFront (and a firewall) back in front

    Once the account verification clears: CloudFront with AWS WAF, a proper domain name, and the security group closed to the CloudFront prefix list only. Removes the open-to-the-world ports and adds caching.

  4. Keep less personal data

    Stop writing the request body (the customer's question) into the nginx log, or mask it, and shorten log retention for requests. Better privacy at no cost.

  5. Automate the restore test

    A weekly job that restores the newest backup into a throwaway container and compares counts with live — the lesson from attempt 1 — and alarms if they differ.
